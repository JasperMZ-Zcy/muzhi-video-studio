## 先选风格，再选镜头

工作室当前提供两种可以选择的风格：

| 风格 | 更适合的内容 | 我们怎么用 |
| --- | --- | --- |
| 杂志插画 | 有人物情境、情绪温度的知识口播 | 保留原来的插画、纸艺、声音和37项质量检查 |
| 档案电流拼贴 | 要把时间、条件、关系和因果讲直观的知识口播 | 让纸、器物、剪报和手发生真实动作；准确文字和关系线用可控后期层 |

新片先把风格锁在这个项目里；同一条片的资料证据、图生动作和知识动效仍可以各司其职。旧杂志项目不会因为插件改名被重做。以后有新风格，会先用真实动态样片验证，再加入选择目录。

### 知识解释镜头库

录好音后，最费时间的常常是给每段话找合适的画面。我们接入完整镜头参考库，先按口播选表现方式，再让镜头适配本片风格。

- 插件现有 **157 张镜头配方** 和 **214 种动效样式** 可供检索参考。它们适合比较、因果、流程、资料、证据和有来源数据等知识段落。
- 导演板前先按口播决定画面路线。人物行为和环境变化交给图生动作，概念解释用知识动效，院校截图和政策原文用可读的局部放大、高亮与出处说明。
- 图生画面和知识动效共用当前项目的 `design.md`。色板、字体、纸张、构图、字幕槽和动效节奏先统一，再进入逐镜制作。
- 这套选择能省去从零想镜头的时间。每条片仍要按自己的口播、审美、素材、预算和平台情况沟通调整。

比如可以直接告诉 Codex。

> 这段在比较两个选择。先用分层卡把条件摊开，再放院校招生简章的真实局部并高亮关键行。人物不出镜，字幕留在底部安全区，整段沿用这条片的 design.md。

镜头配方来自开源项目 [video-shotcraft](https://github.com/Vincentwei1021/video-shotcraft)，我们把它接入口播选镜头、风格适配和后期制作。完整用法和来源边界见[知识解释镜头库](docs/SHOT_LIBRARY.md)。

## 为什么把它整理出来

不露脸口播最费劲的，往往是录完之后。

一边找素材，一边想字幕放哪；好不容易把人物做好，下一镜又换了张脸；画面看着漂亮，动作却跟说话对不上。改一下配乐，还得担心整条视频被重新折腾一遍。

这套流程来自牧之远见多轮实际制作和返工。我们试过不同画面、图生视频渠道、字幕和配乐，也遇到过标题挡人脸、文字漂在卡片外、旧音乐被当作新版本导出的问题。能用程序检查的部分，就让程序检查；需要看画面、听节奏的部分，留下具体的检查要求。

现在把这套做法开源，希望做知识内容的人少花些时间处理这些重复问题。

## 它能帮你完成哪些事

- **把口播变成分镜。** 先弄清每段要让观众明白什么，再设计画面和动作，避免一段文字配一张无关图片。
- **把整条片子的样子做统一。** 人物、道具、色彩、纸张质感有共同参考，换镜头或换平台时不用重新猜画风。
- **把视频接成一条能看的片子。** 检查素材时长、动作和口播的对应关系，处理字幕、音乐与声音，不靠慢放或定格凑时间。
- **让修改停在该改的地方。** 只改封面，就不重做录音和视频；只换音乐，就保留已经满意的画面。
- **把交付弄简单。** 图片、提示词、封面和文案按任务整理，手动生成包同层排镜号，不用一层层翻文件夹。

它还会记录生成任务和文件版本。已有结果能用就复用，任务没返回先查原任务，减少重复提交和重复返工。

## 先按你的情况沟通，再开始做

**我们提供了一套可以直接安装和调用的程序，最终效果仍然需要你按自己的内容去调整。**

你的讲述速度、审美、受众和工具预算，未必与我们相同。可以直接这样告诉 Codex。

> 这条面向刚入门的人，解释慢一点。画面要明亮，别太花。  
> 我想先试一小段，看看人物、字幕和声音合不合适。  
> 这次用 Google Flow，我手动生成；先把首帧和提示词给我。  
> 这个镜头我满意了，后面只改封面。

工作顺序也可以根据实际情况沟通调整。只有录音，就先从录音开始；已经有一批视频，就先接住现有素材；需要手动生成，就先交能直接操作的包。**建议先用一小段把画风、节奏和字幕试顺，再做全片。** 文件核对、声音和必要的画面检查仍要做，流程跑完不等于效果已经满意。

## 怎么开始

在支持插件的 Codex CLI 中执行下面两行命令。

```bash
codex plugin marketplace add JasperMZ-Zcy/muzhi-video-studio
codex plugin add muzhi-video-studio@muzhi-video-studio
```

安装后新开一个任务，选择这个插件，把录音和文稿交给它。

```text
用视频创作工作室做一条不露脸知识口播。先推荐适合这条内容的风格。
这是我的录音和定稿。和我对齐画面感觉、工作顺序和工具选择，
已确认的部分不用反复问。素材和提示词放在同一层。
```

你先提供内容和要求，确定工具与预算；后续哪里不满意，就指出来。需要接着改时，直接说具体位置，不用重新讲一遍整个项目。

详细环境准备与常见问题见[快速开始](docs/GETTING_STARTED.md)。

## 哪些环节用什么工具

| 环节 | 可用方式 |
| --- | --- |
| 理解口播、安排分镜、继续修改 | Codex |
| 知识解释、资料展示与数据动效 | video-shotcraft 镜头配方，按本片设计改造成 Remotion 等本地动画 |
| 插画、首帧、封面 | 当前可用的内置生图或你授权的图像工具 |
| 图生视频 | 自己已配置的本地ComfyUI/MiniMax-H3，或WAN/MiniMax API、Google Flow手动生成；也可接入新平台 |
| 原创配乐 | 例如已连接的ChatCut音乐工具，或其他获得许可的音乐来源 |
| 剪辑、字幕、混音与导出 | 按项目需要使用FFmpeg、Remotion、HyperFrames等已有工具 |

**每条新片的风格和图生视频渠道分别选。** 本地H3只在你已有模型、工作流和足够设备资源时可用；插件不会替你下载模型。中途换平台，已通过的素材保留，后面的合成仍接收同一套镜号、视频文件和时码。

插件包含AI辅助制作流程，但不包含账号、API密钥、模型额度，也不会自动购买服务或替你公开发布。这些工具各自的费用与使用权限需要自行准备。[渠道接入说明](docs/PLATFORMS.md)

镜头库只提供动作和解释思路。它不保证一键适配所有项目，不把 214 种样式说成全部本地渲染通过，也不附赠模型额度或保证播放结果。
