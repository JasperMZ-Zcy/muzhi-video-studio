# Agent Motion：让解释本身变成动作

这是可选的外部动效后端，不是新的画风，也不是图生视频平台。插件内的 Shotcraft、项目风格、本人录音与现有素材可以继续使用；未安装 Agent Motion 或没有相应使用依据时，不阻塞默认制作流程。

## 适合用在哪里

比较两条路、解释一个变化、把资料里的结论展开给观众看。先理解完整口播，再从上游索引找语义匹配的机制：同一个对象怎样接到下一镜，数字怎样和图形同步，资料怎样放大到能读懂。不是给每句话套入场特效。

上游固定版本的参考索引包含 43 个案例。这些是历史观察和实现思路，不是 43 套可直接渲染的模板，也不代表我们已经制作并验收了 43 条影片。

## 开始前需要什么

1. 从 [Agent Motion 原仓库](https://github.com/erduo1998-cell/agent-motion)了解实际许可，取得覆盖自己用途的使用依据；公开仓库不自动意味着商用或再分发自由。
2. 准备独立源码与环境。目前桥接器针对固定提交 `a379a68040b9cb397be3ca4f199201686b673b40` 核验；未来上游更新要先检查兼容性，不能悄悄替换已锁版本。
3. 给制作智能体本项目的完整 SRT、原始录音、`design.md`、风格锁及上游实际路径。使用范围依据由项目真实信息记录，不用示例假装已授权。

## 插件接住哪些工作

- 分别完整读取上游的“理解 SRT”和“制作动效”两个 Skill，并按任务阶段读取必要参考。
- 先看全量索引，再读选中的案例原页；保留口播中的否定、条件、数字、单位和原声时间。
- 将案例来源、口播时码、运动机制、风格适配、可见动作与后续样片证据对应起来。
- 用 `agent_motion_bridge.py check/status/prepare` 核固定入口与案例库、所选输入和项目交接；命令不会渲染影片。
- 交接后由智能体继续完成场景、动画、渲染、原声合成与视听检查。精确资料和数字来自已核事实，不让生成模型画假文字。

完整参数和边界见[随包接入合同](../plugins/muzhi-video-studio/skills/video-production/references/agent-motion.md)。请按命令输出区分“输入准备通过”和“真实影片验收通过”；本仓测试不承诺长片质量、速度或任何平台播放结果。
