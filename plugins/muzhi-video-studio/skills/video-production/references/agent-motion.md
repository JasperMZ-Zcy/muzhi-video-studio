# Agent Motion：可选解释动效后端

新片有知识解释、官方资料或来源数据镜头时，在导演板前读本页并评估是否采用外部 Agent Motion/Three.js。它是解释镜头的可选实现后端，不是第三种风格、图生视频渠道或完整 SRT→成片命令。上游工程独立存放，插件不内嵌上游 Skill、案例正文、代码或资产；使用前以项目实际固定版本和本机检查回执为准。旧片仅在明确局部续作且未确认的镜头中按需评估，不自动重做。

## 先理解口播，再看机制

项目交接须给出固定上游路径中`.agents/skills/srt-reference-to-three/SKILL.md`与`.agents/skills/motion-craft/SKILL.md`两个实际入口，并在制作前完整读它们；按当前任务阶段读完必要原文，不把两个入口装成全局 Skill 抢现有风格路由。先读完整真实 SRT 和已有合格内容分析，核否定、假设、数字/单位、列举、例子、引用归属、前后回调及原声时码精度；缺关键事实不凭动画补造。把“观众此刻应理解什么”写进既有计划，之后才选择镜头机制。上游默认的真人抠像和主持人包装不适用于本片不露脸段。

使用范围依据通过后，先完整读固定版本`reference-library/analysis/INDEX.md`（可对照`catalog.json`）以了解可选机制；只把语义匹配的 Vxx 分析页读完整，不要求每片重读全部43页。案例页是历史观察和实现设想，不是可复用原工程或已经看过原视频。若要宣称复刻或判断原片具体运动，另核合法来源的连续片段；否则仅作为机制启发，并在本片样片验证。无适合案例时在现有计划写原因，继续用 Shotcraft 或原创机制，不硬塞参考。

用户另给喜欢的参考视频时，实际从开头到结尾读取，并按有用时码辨认文字/图片/资料的布局、对象身份如何延续或转移、动作由什么触发、何处停留供阅读，以及声音与画面的语义关系；再写如何服务本片表达。全帧解码不等于逐帧视觉理解，网页摘要或少数海报帧也不能冒充已看完动态。借鉴机制可以改变创意判断，但不得静默覆盖已锁风格；有比较就让关系可见，有变化就让状态真的发生，不能只让几行字飞动。制作中按实际画面迭代，不加用户逐阶段审批。

## 选择与交接

- 先保留本片已锁风格和`design.md`。`visual_route`仍选`native_mg`、`official_evidence`、`sourced_chart`或`hybrid`；只有确由外部工程承载解释动效的段，另写`motion_backend: "agent_motion"`。`hybrid`保留原`responsibilities`；若`uses_image_to_video: true`，再明确且区分`agent_motion_scope`与`image_to_video_scope`，前者只交本地动效后端，后者留给本片已选 H3/其他图生渠道，最终由03合成。分工不清就先拆明子段，不取消混合路线。未标记的段沿原路线。
- 每个选中段先写观众要看懂的因果或比较、进入状态→作用/变化→可读结果→退出衔接、对应真实 SRT 时码、所用 Shotcraft 语义候选或不用的理由。案例库可作机制线索，不直接复刻第三方画面；已有 Shotcraft 镜头库继续可用。
- 选例在现有镜头计划的`reference_cases`中逐项记录：`case_id`（Vxx）、上游相对`source_path`及`source_sha256`、借用的`mechanism`、`srt_timecode`（原 SRT 单条时码，或从一条 cue 起点到后续连续 cue 终点的合法区间）、如何服从本片风格锁与`design.md`的`style_adaptation`、观众实际应看到的`visible_action`、`sample_timecode_evidence: {"status":"pending"}`。计划顶层记录`reference_index_source: "reference-library/analysis/INDEX.md"`与`reference_index_sha256`。准备阶段只能是`pending`；有声动态样片完成后，在本片已有检查记录中填实际媒体、哈希、样片时码和观察，核选中机制真的出现。只有标题、静帧、参数或索引命中不算做到视频里。
- 官方原文、年份、校名、条件、数字、单位和图表口径保留可核来源，精确字由已核原件或本地排版承载；把“原文是什么”和“我们的解释是什么”分层。Agent Motion 只安排可追溯内容的呈现与运动，不替代事实核验，也不把真实资料变成伪造证据。
- 03｜视频制作部独占本片时间线；交接以完整真实 SRT、本人原始录音、项目`design.md`、风格锁、选段计划及各自路径/哈希为依据。外部工程只交回选段媒体及来源/版本/输入输出哈希、实际时长、相邻镜头衔接和检查状态。未经03核对，不替换已确认镜头、不改原声或字幕时码、不直接写最终发布包。

## 准备与停止线

先用插件桥接器只读核上游，再核本片状态；本片的计划和授权回执已由负责人确认后，才准备项目级交接包。`<ROOT>`是插件根，`<UPSTREAM>`是独立固定源码根，`<PROJECT>`是本片根；计划、回执、SRT、录音参数使用项目相对路径，两个 SHA 是实际原件的 SHA-256。命令不会制作影片：

```text
python <ROOT>/scripts/agent_motion_bridge.py check --upstream <UPSTREAM>
python <ROOT>/scripts/agent_motion_bridge.py status --upstream <UPSTREAM> --project <PROJECT>
python <ROOT>/scripts/agent_motion_bridge.py prepare --upstream <UPSTREAM> --project <PROJECT> --plan <PLAN.json> --receipt <RECEIPT.json> --srt <原字幕.srt> --srt-sha256 <SRT_SHA256> --voice <本人原录音.wav> --voice-sha256 <VOICE_SHA256>
```

`prepare`只写项目内`artifacts/agent-motion-handoff.json`，随后用`status`读回核漂移。桥接器核索引与所选 Vxx 原页的路径/哈希、项目锁、`design.md`与输入；它不能证明人已理解全文，也不播放样片。这是交接门，不是影片制作终点：在本片授权内，接手的智能体继续负责内容理解、素材与场景代码、动画、渲染、原声合成、观看/试听检查和受影响修复，直到约定验收条件满足；不把这些步骤转嫁给牧之逐项手动操作。接手者仍须按前述完整阅读。选择 Agent Motion 必须显式，回执的`attestation`、`scope`、项目路径、固定提交和禁止公开再分发边界不得由插件代填；缺项停下。文件存在、准备命令成功或`status`可读，均不等于正式成片通过。

**检查的实际范围**：日常桥接核 5 个关键入口与 47 个案例库文件，不是对独立工程全部源文件和已安装依赖做安全审计。首次获取或升级外部源码时另核来源与完整性；每次准备正式渲染前重新运行上游当前环境诊断，不能拿旧交接包或“环境目录存在”代替今天的运行检查。SRT 结构与时码检查也不证明字幕准确、本人声音身份或语义对应，仍须结合实际音频和画面验收。

使用范围依据可由项目回执记录为`user_attested`，但只能代表回执所写的主体、用途、地点和证据级别；不得由插件自行填写、把口头转述冒充独立核验的书面授权，或默认扩大到公开再分发。缺有效范围依据、缺安装、缺真实输入、哈希漂移或旧项目状态未核时停在准备阶段，明说缺口，不假装`ready`。上游默认真人抠像/人像包装不强加给不露脸片；无人物层就不做该步骤。工具链诊断或合成输入测试，只能证明相应技术范围，不能替代真实有声样片。

正式镜头仍按[共用质量底线](shared-quality.md)及本片风格合同逐时码检查真实动作、准确文字、手机可读和音画同步；杂志插画保留原37项否决。06品牌与07技术各自独立验收，03回收唯一时间线。局部失败只返工受影响段，原素材、哈希、已认可版本与回退路径保留，不要求用户逐张反复审批。
