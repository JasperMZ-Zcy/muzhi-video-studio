# 杂志插画制作

这是已有杂志插画产线的插件入口，不是另一条画风。普通自然语言即可使用，用户不必管理JSON、工具或部门。

**完整产线强制入口**：新项目先读[完整质量合同](references/quality-contract.md)，该合同覆盖旧Skill的全部关键阶段、画面否决和声音/字幕/交付检查；`assets/critical-rules.json`保存逐条旧否决原文与检查路径。续做按当前阶段检索，不因简短入口未重复某条就忽略它。随后读[执行与消耗控制](references/production-and-cost.md)，用实际校验入口与生成台账执行，不能只口头承诺。

## 先接住当前项目

插件根目录为本文件的上两级。先读项目现有`HANDOFF.md`、`artifacts/editorial-job-card.md`和`project.json`，只读当前任务相关内容。执行`python <插件根>/scripts/project_state.py status --project <项目>`读取状态。没有插件状态不等于新项目，不自动重建或重新转写。

获本任务授权后，用`init`创建`artifacts/editorial-plugin-state.json`。它只管理插件版本、当前阶段、项目覆盖、锁定与批准；原`project.json`和旧产线合同仍管理实际业务与媒体事实。二者矛盾时根据最新用户原话、真实文件和已存在回执解决，不能任取一个或重复生产。旧项目需明确导入哪些已完成事项，不把`init`当成历史审批。

### 新知识片先选语义表现路线

新知识片在导演理解、导演板和镜头脚本之前，先读[导演前语义路线](references/pre-director-routing.md)。按口播与证据把每段记录为既有`visual_route`之一，再为`native_mg`、`official_evidence`、`sourced_chart`或`vox_layered_broll`主动从镜头库检索`library_candidates`；镜头库是这些既有路线的解释机制，不能另造`motion-library`路线。人物或环境的真实动作仍是`image_to_video`，需要混合时按既有`hybrid`职责接力。

路线草案可写在现有施工单或导演准备记录附表，并用`python <插件根>/scripts/motion_plan.py validate --project <项目> --plan <路线文件> --stage pre-director`做只读审计。它不生成、不替代原 Gate，也不重开已批准的旧导演板。仅当某段实际走`image_to_video`且本片渠道未知时，才按原渠道规则问一次。

每轮结束同步一份当前施工单摘要，旧段落明确历史。禁止持续在头部堆互相矛盾的“最新”记录。工具的状态文件只是协议，不是不能被用户指令改变的权限系统。

## 保持稳定，允许创意

- 不变项是原始录音和定稿不擅改、字幕准确、有效版本可追溯、原片保留、音轨不串、素材与口播时长匹配、最终发布另获授权。
- 项目风格、情绪、镜头叙事、音乐和封面可自由设计。用户说“这条更温情”只更新本项目；“只改封面”不重跑录音或镜头；“以后都这样”才讨论升级插件默认值。
- 新创意不局限于预置开关。整片新方向才更新项目`design.md`；“只改封面”的创意写入本次封面返工记录，使用revision级`cover.*`覆盖，不改整片设计锁或全局`visual.*`。说明受影响镜头与资产，其他锁定内容不动。必要时新增组件，不改成通用PPT模板。
- 已批准事项不重复问。用户明确要求代理自检或直接批量完成时，记录真实范围后执行；不把旧模板的逐图审核当成反复打断的理由，也不虚构用户看过未生成的东西。
- 金额上限、更多付费变体、公开发布、账号/凭证变更与正式数据删除仍需具体授权。普通创意反馈不是无限生成额度。

用`plan-change --domain covers`等命令先确定最小影响集，`override`仅保存本项目/本次返工要求。新插件版本不能悄悄改老项目的版本锁；状态中的插件版本与当前安装版本不同时，先读被固定的版本资料或解释迁移范围，不能重新初始化覆盖。

`vendor/...`指插件根目录下完整路径，不是可直接执行的字面路径。旧规范的固定审核次数、95%澄清、固定供应商优先级等，是历史默认做法；本入口保留其媒体质量检查，按当前用户任务级授权决定审核频次与供应商。没有真实证据的批准不得补填。

已有delivered/scheduled项目只改封面时，仅使用旧发布包参考中的封面子范围要求；不重建生产合同、不运行全片Gate2—3、不索要历史批准，不改音轨/字幕/镜头。是否替换平台上的已定时帖子属于另外一个外部动作；用户只要求本地封面修改时不自动操作平台，必须明确区分“本地新封面已交付”和“平台定时帖已替换”。

使用旧校验器前阅读所需模板与参数；不关闭检查、不伪造通过，也不修改旧schema字段来让错误内容通关。新项目需要的实际合同按实际证据创建，项目状态工具不替代音画QA。

## 生成与修改

### 镜头库作为解释机制

对新知识片的比较、流程、因果、官方证据与有来源数据段，先按[Shotcraft 知识解释镜头参考](references/shotcraft-integration.md)检索固定来源的 157 张本地文字卡；先`search`得到紧凑候选，再`select`并只`read`需要的 1—3 张。卡文本本地可读不等于生产通过，仍须由本片的`design.md`、事实来源、字幕、声音和质量合同决定。卡不能强迫每句都有动效，也不改变旧片或局部封面任务。

图生视频渠道每条新片都由用户选择，详读[渠道切换与合成解耦](references/video-provider-routing.md)。未指定就问一次，已明确指定就登记并继续；不得默认沿用上一条的平台。WAN/MiniMax走已有API，Google Flow给首帧/提示词单层手动包，临时新平台按API或手动方式接入。中途切换只作用于未提交镜头，旧任务ID/费用/已通过素材保留。合成统一读取供应商无关的本地镜头合同。

生图使用当前可用内置能力及相应技能；用户指定Google Flow手动生成时只准备图与提示词，不自动提交其他视频供应商。ChatCut音乐仍需其已安装工具和用户认可的本次付费范围，插件不附送模型、余额或新账号。

生成前记录输入哈希与任务ID；取回素材检查实际文件内容、时长和哈希，不凭文件名判断新旧。不重新转写同一音频、不对超时任务盲目重提交。后台最多一个本地重任务，线程保守。只有本项目已批准的品牌参数才可继承，不能复制其他项目的样本数或绝对时码。

每个用户实际看过并认可的资产先`lock`再`approve`，`verify`发现文件变化时不得继续声称旧批准有效。执行授权、代理内部质检、用户视觉批准分别记录在当前项目的返工/验收记录，不把“直接做”伪装成用户看过新图。用户授权代理自检时，可`lock`后用`verify --hash-only`核文件一致；返回未获用户视觉批准是正常事实，不再次要求用户逐图批准。语义/美术仍由代理看实际内容；哈希不能证明好看或音乐温情。

## 最后交付

桌面保持一个当前任务入口，图片与提示词同层按镜号排列；封面标题居中、大字、手机可读，审美由当前设计决定。已有文件不盲删，副本替换先验证，原素材和工程回退保留。插件`package`只负责安全平铺复制，不会删除或清理用户文件。

`scheduled`只表示定时已设置；只有真实平台编号、平台与实际时间齐全才能记录`published`。不得用预计八点填成实际发布时间。发布结果与复盘返回原项目及工作台，不自动新建一堆任务。
