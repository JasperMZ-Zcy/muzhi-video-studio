# 先按口播选表现路线，再做导演板

新知识片在导演理解、导演板和镜头脚本创作前，03先读已确认口播及已有证据，按可理解的信息段做语义路线初选。它属于原导演准备，不新增让用户反复批准的环节，也不重开已批准旧项目。用户只改封面等局部任务跳过此步骤。

## 先决定观众需要看见什么

在现有施工单或导演准备记录写明每段口播、观众要理解的意思、画面内的具体变化、选择理由及候选镜头。不要先按平均时长切镜头，不为套库改口播，不先画完导演板再补动效。

- 人物行为、环境变化、情绪表演用`image_to_video`，由本片选定渠道执行；准确政策、学校名、表格数字不能交生成模型写。
- 概念、对比、筛选、因果、步骤用`native_mg`或原有`vox_layered_broll`，默认检索全库选合适配方；没有合适的可原创并写理由，不硬塞模板。
- 官方网页、招生简章、目录条款用`official_evidence`：真实出处定位→局部可读放大→重点标注→解释其意义。原文保持真实，摘录与自己的解释清楚分层。
- 有来源数据的图表用`sourced_chart`，标口径/年份/对象/来源，不照搬示例数字、不截轴制造夸大差异。
- `hybrid`先写清每一部分职责、接棒顺序与唯一主视觉。图生视频负责动作，原始材料负责证据，镜头库负责解释，不能同时抢焦。
- `real_media`沿原流程保留来源与设计适配。

## 本业务的检索起点（候选，不限于这些卡）

用户不用记卡名。执行助手先把业务需要翻译成动作，再检索全库；关键词结果不是语义排名，不能机械选返回的第一条。例如搜“放大”会命中头像轮播，不等于适合院校政策。

| 口播信息任务 | 可先读取的卡 | 必须怎样改造 |
| --- | --- | --- |
| 院校原文定位、指出一条限制 | `scanline-annotate-focus`、`scroll-brake-moves` | 改成真实条款框选/局部放大和稳定停留；去掉示例AI扫描计数、微小英文标注与夸张急刹 |
| 用数份真实材料支撑结论 | `research-card-stack-scroll` | 每份材料可追溯，不能复制同一截图冒充多来源；主证据单独放大可读 |
| 两个方案或政策前后对照 | `before-after-slider-scrub` | 两边有真实对应关系和清楚标签，不人为把一边做模糊/灰暗暗示更差 |
| 分阶段解释路径 | `timeline-travel`、`list-reveal` | 时序钉口播，留中文阅读时间；不照搬宣传片高速掠过 |
| 分类、构成、变化与因果 | `chart-live-moves`、`ring-diagram-annotation-reveal` | 用真实口径与数值，或明确非数值示意；动效不得制造数据差异 |

这些是原卡动作机制在教育讲解中的改造建议，不是上游已经制作好的院校模板，也不代表当前已实渲每一种。

## 两条路线共用设计（执行）

初选时记录风格意图/现有品牌依据；正式导演板阶段把它落实在本项目`design.md`。图生视频首帧、提示词和库组件都从同一份设计派生：人物/插画语言、色板、字体、纸张与材质、构图、字幕槽、运动节奏和转场。不要出现库组件一个风格、图生素材另一套。

由执行助手解释design.md后生成风格参数，不要求用户填JSON。既有`shotcraft_catalog.py validate-style`核设计来源，`shotcraft_style.py`（已安装时）负责结构化主题参数导出；它们不自动理解任意Markdown，也不代替看实际样片。修改设计只复核受影响段落，不重跑已锁定录音、素材或批准。

有图生路线且渠道未知才按现有渠道入口问一次；本次已指定直接沿用。路线初选可保留待查证据和待选渠道，不能假装已确认。进入实际生产前必须补足原质量合同要求。

## 原字段复用与轻量检查

正式故事板仍用既有`visual_route`枚举和原校验器，不改旧schema。路线草案可从现有施工单导出一个小JSON供`python scripts/motion_plan.py validate --project <项目> --plan <路线文件> --stage pre-director`检查；它只审计，不写项目、不调用模型、不替代原Gate。

JSON需要`source_script`（项目相对路径）、`source_sha256`、`style_intent`和`segments`。每段包含`id`、`spoken_text`、`audience_takeaway`、`visual_route`、`reason`、`visual_action`、`library_candidates`（可空但原生解释路线需提供`library_skip_reason`）、`requires_exact_information`、`evidence`（来源条目含ref与verified）、`reading_plan`、`handoff`。图生段另含`generation_action`；混合段另含`responsibilities`和布尔值`uses_image_to_video`，只有确实包含图生动作才需要`generation_action`。真实证据＋本地MG的组合不强迫使用或询问图生渠道。

草案不用编造时间戳、无需提前批准design；原生解释也不能只写“图片缩放”。进入storyboard检查时另外给`design_source: design.md`及真实`design_sha256`，精确信息证据须已核验。实际逐镜时码和语音母钟仍交原故事板校验，禁止重复转写。

全库入口负责取回候选配方和实现，本检查不假装判断候选一定好看或语义一定正确。导演必须亲自核对动作是否对应口播，复杂文字有足够停留，前后场景能接上。
